# Shaping

Three answers shape the outline:

- **Goal** decides the skeleton: which sections exist, and in what order.
- **Audience** decides the voice and what gets emphasised versus tucked away.
- **Depth** decides how much survives.

Every section list below is a default. Drop sections the material can't support, and never pad.

## Goal → skeleton

**Understand.** Lead with *what it is, in one breath*.
Sections: one-line summary → why it exists → the big picture (diagram) → how it works, part by part → key concepts / glossary → examples → where to go next.
Auto format: Document.

**Decide.** Lead with *the ask*: what decision is needed, by whom, and by when.
Sections: the ask → recommendation → context & problem → options compared (table: benefits, costs, risks) → plan / scope (in and out) → timeline & milestones → risks & mitigations → open questions.
Auto format: Document. Use Slides when the material reads like a pitch.

**Catch up.** Lead with *the headline*: what changed or was found, and whether it's good or bad.
Sections: headline + status tiles → key findings or progress (ranked by impact) → evidence & details → issues / blockers → next steps with owners → appendix.
Auto format: Dashboard when there are metrics or many status items, Document otherwise.

**Look up.** Lead with *a map*: what's in here and how to find it.
Sections: overview → quick start / most-used items → topics, grouped logically → reference tables → FAQ / troubleshooting → glossary.
Auto format: Document, with a search box and deep-linkable headings.

## Audience → voice and emphasis

**Mixed team.** Plain language first. Put technical detail (code, schemas, internals) in expandable sections so nobody is blocked and nobody is bored. Define any acronym on first use.

**Leadership & stakeholders.** Outcome-first and short. Emphasise decisions, impact, cost, timeline and risk. Implementation detail appears only where it changes a decision, and stays out of headings.

**Engineers.** Precise. Show architecture and sequence diagrams, interfaces, data models, file paths and identifiers in monospace, plus short code excerpts where they clarify. Surface trade-offs and edge cases.

**Customers / end users.** Friendly second person. Cover what they can do and how, step by step, using screenshots when the sources provide them. Leave internals and team process out. End with FAQ and where to get help.

## Depth → what survives

- **~1 minute**: the lead, decision/status tiles, top 3–5 points, next steps. Everything else goes, except Sources.
- **~5 minutes**: every section of the skeleton, each kept to its key points, with supporting detail in expandable sections.
- **As long as it takes**: everything from the sources, organised for lookup. The skeleton stays scannable while the full depth lives in expandable sections and reference tables.
